## 2. Настанови [G]

- Apple HIG, Charts: стовпчики добре підходять, коли кожне значення — сума за період (крок за день); для стовпчиків нижня межа осі — 0; знайомі послідовності поділок (0, 500, 1 000); заголовок і підсумок головного повідомлення над графіком; не покладатися лише на колір — додавати форму чи візерунок; не вимагати взаємодії для критичної інформації; розширювати зону дотику на всю область графіка; мітки доступності для кожного стовпчика з датою й значенням, без суб'єктивних слів («швидко», «майже»). https://developer.apple.com/design/human-interface-guidelines/charts
- Apple HIG, Tab bars: панель вкладок — для навігації між розділами, не для дій; лишається видимою, крім модальних екранів; підписи з одного слова; зберігає стан кожного розділу. https://developer.apple.com/design/human-interface-guidelines/tab-bars
- Material / Google data-viz: доступність — не лише колір, контраст графіки ≥ 3:1 (WCAG), текстури для розрізнення рядів. https://m2.material.io/blog/data-visualization-accessibility ; https://smashingmagazine.com/2022/07/accessibility-first-approach-chart-visual-design/
- Проєктне дослідження: застосунки підрахунку калорій пов'язані з симптомами РХП у частини користувачів [S12, S13 у `calculation-model.md`] — звідси нейтральна мова, без «зривів», серій і червоного (Q32–Q34).

## 3. Рекомендації [R] і чому

| Питання | Варіанти | Рекомендація |
|---|---|---|
| Ієрархія | графік першим / підсумок першим | Спершу **число-підсумок** (середнє за повні дні + порівняння з ціллю), потім графік — HIG «summarize the main message». |
| Тиждень | 7 стовпчиків / лінія | 7 стовпчиків + лінія цілі + смуга коридору ±100 (стовпчик = сума дня, HIG). |
| Місяць (28–31 день) | 31 стовпчик (YAZIO) / горизонтальна прокрутка / тижневі агрегати + календар | **Тижневі агрегати (4–6 стовпчиків) + календар днів.** 31 стовпчик на 390 pt дає ≈ 9 pt на стовпчик — нижче зручної зони дотику; прокрутка ховає частину місяця й вимагає взаємодії. Календар дає доступ до кожного дня (≥ 44 pt клітинка) і показує повноту без чисел. |
| Пропуски | 0 / порожньо | Порожньо з позначкою «—» (Alma показує знаменник; YAZIO — приклад, як неповний день спотворює середнє). |
| Неповні дні | ховати / показувати | Показувати **контуром** з підписом «неповний» — користувач бачить, що записано, але візуально це не «низьке споживання». |
| Б/В/Ж без цілей (PR-D1) | смужки прогресу / три картки / графік із вибором нутрієнта | **Три компактні картки в ряд** з г/день. Смужки прогресу без цілі нічого не означають; окремий графік — зайва складність для v1. |
| Деталі дня | інлайн під графіком / шторка | **Шторка знизу** — як CT-03/CT-08 у проєкті; не зсуває сторінку; закривається свайпом. |
| Навігація | іконка в CT-01 / вкладки | Вкладки «Сьогодні / Прогрес» (рішення PR-D3, HIG Tab bars). |
| Інсайти | LLM / правила | Детерміновані правила (≤ 2), без оцінок, медичних тверджень і прогнозів ваги. |
| Колір | червоний/зелений для понад/нижче | Ні: у low-fi лише сірий; у фінальному дизайні діапазони передаються словами й символами, колір — не єдиний носій. |
