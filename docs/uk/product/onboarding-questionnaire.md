# Анкета онбордингу — запитання, відповіді й параметри розрахунку

Статус: **пропозиція для затвердження**. Екрани — у `onboarding-flow.md` (ON-xx), формули — у `calculation-model.md`, обґрунтування UX — у `../research/onboarding-research.md`.

Принцип відбору: **мінімум, достатній для розумної стартової оцінки**. Кожне запитання пройшло перевірку трьома тестами:
1. *Чи змінює відповідь норму більш ніж на ~50 ккал або вмикає правило безпеки?* Якщо ні — прибрати або відкласти.
2. *Чи можна отримати це пізніше точніше* (з даних, з пристрою, у контексті)? Якщо так — відкласти.
3. *Чи можна спитати простіше* (вибір замість числа, діапазон замість точного значення)? Якщо так — спростити.

Технічні терміни (BMR, TDEE, PAL, MET, ІМТ) користувач не бачить ніде в онбордингу.

**Екранів із запитаннями:** 7 (ON-02…ON-08), для «Підтримувати» — 6.

## 2. Картки запитань

### Q-01 Мета — ON-02

| | |
|---|---|
| **Запитання** | «Чого ви хочете досягти?» |
| **Варіанти** | «Схуднути» · «Підтримувати вагу» · «Набрати вагу» |
| **Пояснення під запитанням** | «Від цього залежить, чи додамо до вашої норми дефіцит або запас калорій.» |
| **Навіщо** | Визначає знак і наявність дефіциту, потребу в запитаннях 6 і 13, тексти результату. |
| **Параметр** | `goal ∈ {lose, maintain, gain}` → `calculation-model.md` §4 |
| **Обов'язкове** | так |
| **Можна пізніше?** | ні — без нього норма невизначена |
| **Простіше?** | уже мінімальне: 3 варіанти, одне натискання з автопереходом |

### Q-02 Стать для розрахунку — ON-03

| | |
|---|---|
| **Запитання** | «Стать для розрахунку» |
| **Варіанти** | «Жіноча» · «Чоловіча» · «Не вказувати» |
| **Пояснення** | «Формули енергообміну різні для жіночого й чоловічого організму.» |
| **Навіщо** | Константа в Міффліні (різниця 166 ккал) і нижній поріг норми; показ варіантів вагітності/годування на ON-05. |
| **Параметр** | `sex_for_calc ∈ {female, male, unspecified}` → BMR −161 / +5 / −78; поріг 1 200 / 1 500 / 1 350 |
| **Обов'язкове** | так (але «Не вказувати» — повноцінний варіант) |
| **Можна пізніше?** | ні |
| **Простіше?** | формулювання «для розрахунку» замість «стать» — чесно пояснює, що питаємо про фізіологію для формули, а не про ідентичність. «Не вказувати» — компроміс (Q3). |

### Q-03 Рік народження — ON-03

| | |
|---|---|
| **Запитання** | «Рік народження» |
| **Варіанти** | колесо вибору року (від поточного − 100 до поточного), прокрутка стартує з 1990 |
| **Пояснення** | спільне для блоку: «Потрібно, щоб оцінити, скільки енергії ваше тіло витрачає в спокої.» |
| **Навіщо** | Вік у Міффліні (−5 ккал/рік); перевірка < 18. |
| **Параметр** | `birth_year` → `age = поточний рік − birth_year` |
| **Обов'язкове** | так |
| **Можна пізніше?** | ні |
| **Простіше?** | рік замість повної дати: похибка ±1 рік = ±5 ккал — неістотно; рік (а не вік) зберігає коректність з часом. |

| | |
|---|---|
| **Запитання** | «Зріст, см» |
| **Варіанти** | цифрове поле, ціле, допустимо 100–250 |
| **Навіщо** | Міффлін (+6,25 ккал/см); ІМТ для перевірок безпеки. |

| **Обов'язкове** | так |

### Q-05 Поточна вага — ON-04

| | |
|---|---|
| **Запитання** | «Зараз, кг» |
| **Варіанти** | цифрове поле, 1 знак після коми, допустимо 30–300 |
| **Пояснення** | «Можна приблизно — уточните, коли зважитеся.» (знижує бар'єр; так робить і MyFitnessPal — див. дослідження) |
| **Навіщо** | Міффлін (+10 ккал/кг), MET-витрата тренувань, ІМТ. |
| **Параметр** | `weight_kg`; **також створює перший запис `WeightEntry(source=onboarding, estimated=true)`** для адаптивної моделі |
| **Обов'язкове** | так |
| **Можна пізніше?** | ні; але точність — пізніше (перше зважування) |
| **Простіше?** | так, дозволено приблизне значення |

### Q-06 Бажана вага — ON-04 (необов'язкове)

| | |
|---|---|
| **Запитання** | «Бажана вага, кг» з позначкою «необов'язково» |
| **Показ** | лише для `goal ∈ {lose, gain}` |
| **Пояснення** | «Не змінює денну норму. Покажемо, скільки лишилося до мети.» |
| **Навіщо** | Прогрес «78 → 68 кг»; перевірка напрямку (для схуднення < поточної, для набору > поточної); перевірка ІМТ ≥ 18,5; момент, коли запропонувати перехід на підтримку. |
| **Параметр** | `goal_weight_kg` — **не входить у формулу норми** |
| **Обов'язкове** | ні |
| **Можна пізніше?** | так — у профілі |
| **Простіше?** | так: можна взагалі не вводити. Розділяємо «куди» (бажана вага) і «як швидко» (темп) — саме темп визначає дефіцит. |

### Q-07 Анкета безпеки — ON-05

| | |
|---|---|
| **Запитання** | «Чи стосується вас щось із цього?» |
| **Варіанти (множинний вибір)** | «Вагітність»*, «Годую груддю»*, «Розлад харчової поведінки — зараз або в минулому», «Захворювання, через яке лікар контролює моє харчування (наприклад, діабет на інсуліні, хвороба нирок)». *Лише для «Жіноча» / «Не вказувати». |
| **Основна кнопка** | «Нічого з цього», коли нічого не позначено; «Далі», коли позначено хоча б одне |
| **Пояснення** | «Так ми не запропонуємо план, який може зашкодити.» |
| **Навіщо** | Вимикає розрахунок дефіциту там, де він небезпечний (`calculation-model.md` §5). |
| **Параметр** | `safety_flags ⊆ {pregnant, breastfeeding, eating_disorder, medical_supervision}` |
| **Логіка** | `pregnant`/`breastfeeding`/`eating_disorder` → ON-11; `medical_supervision` → розрахунок дозволено, «Активно» вимкнене, порада на ON-09 |
| **Обов'язкове** | так, але коштує одне натискання |
| **Можна пізніше?** | ні — це запобіжник перед показом числа |
| **Простіше?** | один екран із чекбоксами замість окремих «так/ні»-запитань; без деталей і діагнозів |

### Q-08 Робота / основна діяльність — ON-06

| | |
|---|---|
| **Запитання** | «Як минає ваш звичайний день?» з підказкою «Подумайте про роботу, навчання чи домашні справи.» |
| **Варіанти** | «Переважно сиджу» — «офіс, навчання, за кермом» · «Переважно стою» — «продавець, викладач, перукар» · «Багато ходжу» — «кур'єр, офіціант, медсестра» · «Важка фізична робота» — «будівництво, склад, сільське господарство» |
| **Навіщо** | Найбільша складова відмінностей у витраті між людьми. |
| **Параметр** | `work_activity` → PAL_робота 1,40 / 1,50 / 1,60 / 1,75 |
| **Обов'язкове** | так |
| **Можна пізніше?** | ні |
| **Простіше?** | так — уже описові варіанти з прикладами замість «рівнів активності»; коефіцієнт ніколи не показується |

### Q-09 Щоденний рух — ON-06

| | |
|---|---|
| **Запитання** | «А поза роботою?» |
| **Варіанти** | «Рухаюся мало» — «до 5 тис. кроків» · «Як більшість» — «5–10 тис. кроків» · «Багато ходжу» — «понад 10 тис. кроків, пішки чи велосипедом» |
| **Пояснення** | «Не знаєте кроків? Обирайте за відчуттям.» |
| **Навіщо** | Друга складова PAL (±0,05…0,10 ≈ −75…+150 ккал). |
| **Параметр** | `daily_movement` → Δ_рух −0,05 / 0 / +0,10 |
| **Обов'язкове** | так |
| **Можна пізніше?** | так, точніше — кроками з телефона (Q5); тоді відповідь замінюється виміряним середнім |
| **Простіше?** | 3 діапазони замість числа кроків; цифри кроків лише як орієнтир |

### Q-10 Частота тренувань — ON-07

| | |
|---|---|
| **Запитання** | «Чи тренуєтесь ви?» · підказка «Рахуємо лише навмисні тренування — прогулянки вже враховані.» |
| **Варіанти** | «Ні» · «1–2 рази» · «3–4 рази» · «5+ разів» (на тиждень) |
| **Навіщо** | Тренування як окрема складова витрати (ккал/день). |
| **Параметр** | `exercise_freq` → 0 / 1,5 / 3,5 / 5,5 сесії на тиждень |
| **Обов'язкове** | так |
| **Простіше?** | діапазони замість числа |

### Q-11 Тип тренувань — ON-07 (умовне)

| | |
|---|---|
| **Запитання** | «Які переважно?» |
| **Показ** | лише якщо Q-10 ≠ «Ні» (прогресивне розкриття) |
| **Варіанти** | «Легкі» — «йога, розтяжка, пілатес» · «Помірні» — «силові, плавання, танці, велосипед» · «Інтенсивні» — «біг, HIIT, командні ігри, єдиноборства» |
| **Параметр** | `exercise_kind` → MET 3 / 5 / 8 |
| **Обов'язкове** | так, якщо показано |
| **Простіше?** | 3 рівні з прикладами замість переліку видів спорту; змішані тренування — «переважно» |

### Q-12 Тривалість — ON-07 (умовне)

| | |
|---|---|
| **Запитання** | «Скільки зазвичай триває?» |
| **Варіанти** | «30 хв» · «45 хв» (обрано за замовчуванням) · «1 год» · «1,5 год+» |
| **Параметр** | `exercise_minutes` → 30 / 45 / 60 / 90 |
| **Обов'язкове** | має значення за замовчуванням |
| **Чому залишили** | різниця між 30 і 90 хв — утричі більша витрата (для Олени 78 vs 234 ккал/день) — більше за поріг 50 ккал. Значення за замовчуванням прибирає зайву дію для більшості. |

### Q-13 Темп — ON-08 (умовне)

| | |
|---|---|
| **Запитання** | «Схуднути»: «Як швидко хочете рухатися?»; «Набрати»: те саме |
| **Варіанти (схуднення)** | «Легко · ≈0,25 кг на тиждень · {норма} ккал на день» · «Комфортно · ≈0,4 кг на тиждень · {норма}» з позначкою «Рекомендовано» · «Активно · ≈0,6 кг на тиждень · {норма}» |
| **Варіанти (набір)** | «Легко · ≈0,25 кг…» (рекомендовано) · «Активно · ≈0,5 кг…» |
| **За замовчуванням** | рекомендований варіант (або найшвидший доступний, не швидший за рекомендований) |
| **Недоступні варіанти** | неактивні з підписом «Недоступно для ваших даних — дефіцит був би завеликим» або «Через стан здоров'я пропонуємо не швидше помірного темпу» |
| **Пояснення** | «Комфортний темп легше втримати. Змінити можна будь-коли.» |
| **Навіщо** | Плановий дефіцит/запас. Показ норми на кожній картці робить компроміс зрозумілим без теорії. |
| **Параметр** | `pace` → `calculation-model.md` §4.2–4.3 |
| **Можна пізніше?** | так (у профілі), але норма без нього невизначена — тому значення за замовчуванням |

## 4. Модель даних онбордингу (зберігається з першого дня)

```
OnboardingAnswers {            // незмінний знімок, новий при кожній зміні
  id, user_id, created_at, model_version
  goal, sex_for_calc, birth_year, height_cm, weight_kg, goal_weight_kg?
  safety_flags[]
  work_activity, daily_movement
  exercise_freq, exercise_kind?, exercise_minutes?
  pace?
}
WeightEntry { user_id, measured_at, kg, source: onboarding|manual|device, estimated: bool }
CalorieEstimate { … див. calculation-model.md §6 }
```

Відповіді — **сирі значення варіантів** (`sitting`, `3-4`), а не коефіцієнти: якщо коефіцієнти зміняться, історичні розрахунки можна перерахувати й порівняти.

## 5. Відкинуті й відкладені запитання

| Запитання | Рішення | Чому |
|---|---|---|
| Ім'я | відкладено (профіль) | не впливає на розрахунок |
| Створення акаунта, e-mail | відкладено до моменту, коли є що зберігати | обов'язкова реєстрація перед використанням — одна з причин раннього відмовлення від застосунків [R5] |
| Одиниці (фунти, фути) | відкладено: лише кг/см у MVP (Q4) | цільова аудиторія метрична |
| Дата досягнення мети | не питаємо і не показуємо (D9) | лінійні прогнози переоцінюють швидкість (`calculation-model.md` §4.5) |
| Підключення кроків (Apple Health / Health Connect) | після онбордингу (Q5) | дозволи на старті — зайвий бар'єр; кроки уточнять `daily_movement` |
| Нагадування | після першого запису їжі (поза цим документом) | встановлення нагадування пов'язане з довшим використанням [R2]; доречніше просити в контексті |
| Частота зважувань / перше зважування | після онбордингу | потрібне для адаптивної моделі, але не для старту |
| Відсоток жиру, обхват талії | не питаємо | більшість не знає; для Міффліна не потрібні |
| Харчові вподобання, дієта, макроелементи | не питаємо в онбордингу | не впливають на калорійну норму; «не вчити теорії харчування» |
| Мотивація («навіщо вам це»), джерело трафіку | не питаємо | не впливає на розрахунок; подовжує анкету |
| Сон, стрес, ліки | не питаємо | ефект не моделюється; детальні медичні дані — не наша зона |
| Кількість кроків числом | замінено діапазонами (Q-09) | мало хто знає своє середнє |
| Точна дата народження | замінено роком | ±5 ккал |
| Окремі запитання «вагітні?», «годуєте?» тощо | об'єднано в один екран ON-05 | одне натискання для більшості |
