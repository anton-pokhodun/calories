# Обсяг MVP (Етап 1 — базовий MVP)

Статус: **запропоновано; змінено рішеннями власника 2026-11-20** (див. нижче) · Дата: 2026-11-20
Пов'язані: [product-feature-map.md](product-feature-map.md) · [product-roadmap.md](product-roadmap.md) · [decisions.md](decisions.md)

> **Рішення власника 2026-11-20** ([decisions.md](decisions.md)): фото / AI (F-28) і штрихкод (F-19) лишаються в MVP за Q8 — SD-01, SD-02 відхилено; Прогрес · тиждень, панель вкладок і рядок тижня (F-20/21, F-22) — у MVP, SD-03 відхилено; мінімальні налаштування (F-16) — затверджено, SD-07.

## Визначення MVP
Нова людина за одну сесію і без акаунта може: відповісти на запитання онбордингу, отримати безпечну персональну норму калорій (або план без норми), швидко записувати їжу (одним списком за день, без прийомів), виправляти помилки і бачити прогрес за сьогодні відносно норми. Реліз дає змогу виміряти активацію і раннє утримання логування.

**Не в MVP:** облік ваги, нагадування, місячна аналітика, перевірка «малого» дня (SD-04, SD-05 — відкриті), пейвол. Це Етапи 2–3, бо вони або потребують даних, яких у перший день немає, або монетизують ще не підтверджену цінність.

## 2. Використання вайрфреймів у MVP

### 2.1 Використати без змін
- **Онбординг:** ON-01, ON-02, ON-03, ON-04, ON-05, ON-06, ON-07, ON-08, ON-10, ON-11 та їхні стани; гілка безпеки.
- **Базовий потік:** CT-03 (порція), CT-04 (редагування), CT-08 (ввести вручну), шторка позицій сесії, повідомлення зі скасуванням; кадри CT-02 «Нещодавнє» / «Збережене» / введення / результати / перше використання / офлайн (крім іконки, див. нижче); CT-07 і його стани (якщо штрихкод входить).
- **Стани CT-01:** порожній день, інший день без записів, частковий, у межах плану, понад план, завантаження.

### 2.2 Наявні вайрфрейми, які варто відкласти (зберігаються як референс)
- Ряди перевірки «малого» дня (сторінка 03 Progress) → **пізній Етап 2 або Етап 5**.
- PR-02 місяць → **Етап 3**.

### 2.3 Відсутні екрани чи потоки, потрібні для MVP
| # | Що відсутнє | Примітки |
|---|---|---|
| 3 | **Згода / повідомлення про конфіденційність** при першому запуску | Є заглушка (ON-12, D21); розташування і текст — з юристом (OQ-07), не подовжувати онбординг |
| 5 | Повідомлення про джерело / ліцензію бази продуктів (якщо цього вимагає обраний постачальник) | Залежить від OQ-03 |
| 6 | Екран запуску / завантаження і загальний екран помилки | Невеликі; можуть бути системними |

### 2.4 Функції, які поки не варто розробляти
Голосове логування, місячна аналітика (SD-05 відкрито), перевірка «малого» дня, адаптивний двигун норми, типи харчування й цілі Б/В/Ж у «Прогресі» (SD-13), інтеграція з Health, система акаунтів (до рішення OQ-05), будь-яка гейміфікація, соціальні функції, облік тренувань / води / голодування.

## 3. Швидкі шляхи, які MVP має зберегти
| Шлях | Ціль |
|---|---|
| Повторний продукт, типова порція | Сьогодні → плаваюча + → + на рядку «Нещодавнє» → Готово = **3 натискання**, без введення тексту (D7) |
| Новий продукт, своя порція | + → ввести → натиснути рядок → змінити → Додати → Готово |
| Від першого запуску до першого запису | Вітання → 7 кроків запитань → Ваш план → Записати першу їжу (D10) |
